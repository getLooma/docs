## Requirements

### Requirement: Every page has a unique title and description

Every page's frontmatter SHALL have a `title` of at most 60 characters and a `description` of 50
to 160 characters, enforced by the content collection schema in `src/content.config.ts`, so the
build fails without them. No two pages SHALL share a title or a description. Each built page SHALL
render the title in `<title>` and the description in `<meta name="description">`.

#### Scenario: A page without a description fails the build

- **WHEN** a page's frontmatter has a `title` but no `description`
- **THEN** `just build` fails and names the page

#### Scenario: Duplicate descriptions fail the check

- **WHEN** two pages have the same `description`
- **THEN** `just check` fails and names both pages

### Requirement: Built pages are clean semantic HTML

Every built page SHALL have exactly one `h1` (the page title), headings that never skip a level,
lists and tables as real `ul`/`ol`/`table` elements, and an `alt` attribute on every content
image, non-empty unless the image is marked decorative. Every fenced code block in a page source
SHALL name its language. Page sources SHALL NOT use `client:*` hydration directives, so no content
depends on client-side JavaScript to appear.

#### Scenario: A second h1 fails the check

- **WHEN** a page's Markdown body starts with `# Heading`
- **THEN** `just check` fails, because the built page has two `h1` elements

#### Scenario: A skipped heading level fails the check

- **WHEN** a page goes from `##` straight to `####`
- **THEN** `just check` fails and names the page and the heading

#### Scenario: An image without alt text fails the check

- **WHEN** a page contains `![](../../assets/inbox.png)`
- **THEN** `just check` fails and names the page and the image

#### Scenario: A code block without a language fails the check

- **WHEN** a page contains a fenced code block with no info string
- **THEN** `just check` fails and names the page and line

### Requirement: The site publishes llms.txt files

The build SHALL emit `/llms.txt` (the site name, a summary, and every page as a link to its
Markdown copy with the page's `description` as its one-line summary, grouped by section),
`/llms-full.txt` (every page's Markdown in one file, in sidebar order) and `/llms-small.txt`, plus
one bundle per section that holds pages, all generated by `starlight-llms-txt`. Pages excluded
from the sitemap SHALL also be excluded from these files.

#### Scenario: llms.txt lists every page

- **WHEN** `just check` inspects `dist/llms.txt`
- **THEN** it is non-empty and holds one entry per built page, each with that page's description

#### Scenario: llms-full.txt holds every page

- **WHEN** `just check` inspects `dist/llms-full.txt`
- **THEN** it is non-empty and contains the title of every built page

### Requirement: Every page has a Markdown copy

For every page at `/<path>/` the build SHALL emit its Markdown at `/<path>.md` (the home page at
`/index.md`), starting with the page title as an `h1` and its description, without
frontmatter, MDX imports or component markup. Every HTML page SHALL link to its copy with
`<link rel="alternate" type="text/markdown">` and SHALL offer "Copy page as Markdown" and "Open in
ChatGPT" / "Open in Claude" actions (`starlight-page-actions`).

#### Scenario: Each page has its Markdown twin

- **WHEN** `just check` walks `dist/`
- **THEN** it fails if any `<path>/index.html` has no `<path>.md`, or if a `.md` copy contains
  `import ` lines or frontmatter

#### Scenario: The alternate link points at the copy

- **WHEN** a built page `/inbox/conversations/` is inspected
- **THEN** it has `<link rel="alternate" type="text/markdown" href="/inbox/conversations.md">`

### Requirement: Markdown is served on content negotiation

The production server SHALL answer a `GET` for a page URL carrying `Accept: text/markdown` with
that page's Markdown copy, `Content-Type: text/markdown; charset=utf-8`. Every page response SHALL
carry `Vary: Accept`. A request without `text/markdown` in `Accept` SHALL get the HTML page.

#### Scenario: An agent asks for Markdown

- **WHEN** the image's smoke test requests `/getting-started/` with `Accept: text/markdown`
- **THEN** the response is 200 with `Content-Type: text/markdown; charset=utf-8` and the body of
  `/getting-started.md`

#### Scenario: A browser gets HTML

- **WHEN** the smoke test requests `/getting-started/` with `Accept: text/html`
- **THEN** the response is the HTML page with `Vary: Accept`

### Requirement: robots.txt allows search and AI crawlers

The build SHALL emit `/robots.txt` allowing all crawlers, with explicit `Allow: /` groups for at
least GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, Claude-SearchBot,
PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended, CCBot and Bingbot, a
`Sitemap:` line with the absolute sitemap URL, and a comment pointing to `/llms.txt`.

#### Scenario: robots.txt names the AI crawlers and the sitemap

- **WHEN** `just check` inspects `dist/robots.txt`
- **THEN** it contains an `Allow: /` group for each listed user agent, no `Disallow: /` line, and
  `Sitemap: https://docs.getlooma.io/sitemap-index.xml`

### Requirement: The sitemap lists every page

The build SHALL emit `sitemap-index.xml` and its sitemap files (Starlight's built-in sitemap
integration, from `site: 'https://docs.getlooma.io'`) listing the canonical URL of every page and
no redirect source.

#### Scenario: Sitemap is generated and complete

- **WHEN** `just check` inspects the built sitemap
- **THEN** it is non-empty, lists every built page's canonical URL, and lists no redirect source

### Requirement: Pages carry canonical, social and language metadata

Every page SHALL have `<html lang="en">`, a `<link rel="canonical">` with the absolute,
trailing-slash URL of the page, Open Graph tags (`og:title`, `og:description`, `og:url`,
`og:type`, `og:image`, `og:site_name`) and Twitter tags (`twitter:card` = `summary_large_image`).
`og:image` SHALL be a 1200×630 PNG generated per page at build time (`astro-og-canvas`).

#### Scenario: Canonical and Open Graph tags are present

- **WHEN** `just check` inspects every built page
- **THEN** each has `lang="en"`, a canonical URL equal to its own absolute URL, all listed Open
  Graph and Twitter tags, and an `og:image` file that exists in `dist/`

### Requirement: Pages carry structured data

Every page SHALL include JSON-LD with an `Organization` (Looma, its site URL, its logo) and a
`BreadcrumbList` matching the page's section path. Every content page SHALL also include a
`TechArticle` with its headline, description and last-modified date. A page whose frontmatter sets
`faq` (a list of questions and answers) SHALL include an `FAQPage` built from that list, and the
same questions SHALL appear as headings on the page.

#### Scenario: JSON-LD parses and matches the page

- **WHEN** `just check` inspects every built page
- **THEN** every `application/ld+json` block parses as JSON, the `BreadcrumbList` items match the
  page's URL segments, and the `TechArticle` headline equals the page title

#### Scenario: FAQ page emits FAQPage

- **WHEN** the FAQ page with a `faq` frontmatter list is built
- **THEN** it includes an `FAQPage` whose questions equal the list's questions

### Requirement: A removed page leaves a permanent redirect

`published-routes.txt` SHALL list every route the site has ever published. Every route in it
SHALL be either a built page or a source in `redirects.json`, and every built page SHALL be listed
in it. Every redirect target SHALL be a built page (no chains, no loops). The production server
SHALL answer each redirect source with a `301` to its target. `just routes` SHALL add new pages to
the manifest and never remove a route.

#### Scenario: Deleting a page without a redirect fails

- **WHEN** a page is deleted and `redirects.json` is unchanged
- **THEN** `just check` fails and names the route that no longer resolves

#### Scenario: A new page must be recorded

- **WHEN** a page is added and `just routes` was not run
- **THEN** `just check` fails and says to run `just routes`

#### Scenario: Redirects answer with 301

- **WHEN** the image's smoke test requests a redirect source from `redirects.json`
- **THEN** the response is `301` with `Location` set to the target

### Requirement: Pages stay light

Every built page SHALL ship no more client JavaScript than the budget recorded in
`scripts/budget.json` (set from the first build plus 20 percent). Images under `src/assets/` SHALL
be processed by Astro's image pipeline, with width and height set.

#### Scenario: Over-budget JavaScript fails

- **WHEN** a change makes a page's total `<script>` payload exceed the budget
- **THEN** `just check` fails, naming the page and its size
